# devlog 20260828 · LLM 自动语气 + 设置面板

## 用户需求
新项目囊括旧项目功能并更自动化：上传小说 →（可选）LLM 自动拆解分段并逐段生成语气指令 → 驱动 TTS 带语气合成 → 合并 mp3。设置面板统一管理 TTS API Key 与 LLM（OpenAI 兼容）Key / Base URL / Model，自动语气可手动开关且依赖 LLM 可用。

## 实现
- 新增 `src/llm.ts`：OpenAI 兼容 Chat 客户端；`annotateNovel()` 按段落边界分块（~4000 字/块）调用 LLM，输出格式沿用旧项目 `语气指令 <|endofprompt|> 原文段`，逐行解析为 `{text, instruct}`；单块调用失败或丢字覆盖率 <90% 时该块回退为纯规则拆句；超长段沿用同指令二次切细
- `src/pipeline.ts`：`PipelineOptions` 新增 `autoStyle` / `onStatus`；autoStyle 且 LLM 已配置 → LLM 拆解逐段带语气合成，否则走原 `splitIntoSegments` + 全局 style 兜底；未改 `TTSProvider` 接口（`synthesize` 的 `style` 本就是 per-call）
- `src/server.ts`：`/api/status` 追加 `llm` 字段（configured / baseUrl / model / autoStyleEnabled，key 不回传）；新增 `POST /api/config/llm`（key 留空保留旧值）与 `POST /api/config/autostyle`（开启前校验 LLM 已配置）；`/api/convert` 与 `/api/convert/file` 支持 `autoStyle` 透传
- `public/index.html`：设置面板拆为「TTS 配置」「LLM 配置」两卡；自动语气为滑动开关，LLM 未配置时置灰；转换卡在开关开启时展示「自动语气：开」徽标并随请求下发 `autoStyle`
- `.env.example`：补充 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` / `AUTO_STYLE_ENABLED`

## 验证
- `npm run typecheck` 通过
- 手测路径：LLM 未配置 → 开关置灰，转换走旧流程；LLM 已配置 + 开关开 → 转换时 `/api/progress` 先显示「LLM 拆解中 x/y 块」再进入逐段合成

## 备注
- 所有 Key 均存 `.env`，通过 WebUI 写入，未硬编码；LLM 配置接口对 key 脱敏（不回显）
- 待办：开场/结束语、单帧视频合成（沿用旧项目思路，后续轮次再做）

## 修复：自动语气开关无法点击
- 原因：开关的隐藏 `<input>` 为 `opacity:0; width:0; height:0`，外层用的是 `<span>` 而非 `<label>`，点击滑块不会触发 checkbox 的 `change` 事件，开关"点不动"
- 修复：`<span class="switch">` 改为 `<label class="switch" for="autoStyleToggle">`，浏览器实测可正常来回切换
- 后端链路（保存 LLM 配置 → 状态查询 → 开关切换）经 curl 实测本身是通的
